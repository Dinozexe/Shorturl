Architecture

Micro-service 3 ตัว แยกหน้าที่ชัดเจน สื่อสารกันผ่าน HTTP ภายใน และ Redis

บริการหน้าที่ที่รัน
frontendหน้าเว็บ (Next.js export เป็น static) + หน้าเอกสารนี้Cloudflare Workers (static assets) · shorturl.kittametdev.com
core-apiAuth, ลิงก์, QR, admin, API key, guestRender · api.kittametdev.com
redirect-serviceเปิดลิงก์สั้น → 302 ให้เร็ว (cache Redis) และเข้าคิวคลิกRender · s.kittametdev.com
analytics-serviceประมวลผลคิวคลิก, ให้สถิติแก่ core-apiRender (ภายใน, ป้องกันด้วย x-internal-key)
PostgreSQL 16ข้อมูลหลักทั้งหมดNeon
Redis 7cache, session, rate limit, ตัวนับ, คิวUpstash

การไหลสำคัญ

  • ย่อลิงก์ — เบราว์เซอร์ → core-api ตรวจ URL/โดเมนต้องห้าม → บันทึก links → ลบ cache เก่า
  • เปิดลิงก์ — redirect-service อ่าน Redis (ไม่มีค่อยอ่าน DB แล้ว cache 1 ชม.) → ตรวจเงื่อนไข → 302 → เข้าคิวคลิกแล้วแจ้ง analytics ให้ flush
  • สถิติ — analytics ดึงคิวเป็น batch เขียนลง DB; หน้า stats เรียก core-api → analytics (ถ้าล่ม แสดงยอดรวมจาก click_count)
